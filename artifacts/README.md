# artifacts/ — co-built work products

A shared workspace: slide decks, HTML pages, documents, and other work products you and the agent build together. Any file type. Agents create and edit artifacts here freely: shared edit access is the point of the folder. Log a non-trivial edit in the day log so you can see what moved. Nothing here is walked, swept, or ingested by the pipeline.

**Organize by project.** An artifact tied to a project lives in a subfolder named for that project's bundle: `artifacts/krux/` mirrors `wiki/projects/krux/`. The project hub links to its artifact folder, and artifacts embed-link from any page where they're relevant, so from the hub everything about a project is one hop away. Artifacts with no project home live at this folder's root, and the root holds nothing else. When a new artifact clearly belongs to a project, file it in that project's subfolder from the start, creating the subfolder as needed.

Everything here is readable and linkable — "here is a link to a thing" carries no authorship claim. But authorship inside a co-built file is mixed, so nothing here evidences what anyone said. An artifact does evidence its own existence and the work done on it, and its contents evidence where attention was and what the user cared about, cited as inference and never as a quote or a claim of theirs (the user's ruling, 2026-09-04). If a claim in an artifact matters enough for the wiki, capture it to sources/inbox/ with a speaker — attributed words are what the pipeline can read.

Large binaries snapshot poorly in git and count against Obsidian Sync — exclude this folder from Sync on devices where size matters.
