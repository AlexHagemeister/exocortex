Agent knowledge: what Claude's surfaces, tools, and harnesses can do on this deployment, and how agents should perform recurring tasks for the user. Pages here answer "how should an agent do X" and "what can this tooling actually do." **Boundary with craft/:** craft/ holds the user's principles and sensibilities and the why behind them. This folder holds their instantiations, the specific instructions and mechanics those sensibilities produce. Interlinking is the design, not a smell: a page here should cite the craft/ principle it instantiates, and craft/ pages may point here for the current mechanics. When a page drifts into stating the user's judgments rather than citing them, that content belongs in craft/. **Boundary with skills:** a skill is an invocable procedure with a trigger. Pages here are reference knowledge an agent consults while working. When a page's content hardens into a repeatable procedure, propose a skill and leave the page as its background. **Boundary with the rules layer** (where "remember to always X" goes), three questions in order: (1) Does an existing rule surface (CLAUDE.md, a skill, a folder README) already own it? Then it is an `amend`. (2) No owner: is there a fetch moment that reliably precedes the behavior? Then it is a page here, entering via the pipeline. (3) Neither answers cleanly: default to the pipeline and flag the amend candidate to the user. Recurrence escalates a page into a rule (roughly three of the same), never the first utterance. **Churn:** faster than craft/ by nature (harness updates, tool changes). Update eagerly via the pipeline, and treat a page that lags the real tooling as worse than a draft. **Grain:** one capability area or task pattern per page, scoped by its fetch moment ("fetch before X"). Never shipped in a public bundle without a redaction pass (deployment specifics live here).
