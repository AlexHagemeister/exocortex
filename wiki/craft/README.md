Craft knowledge: how the user works — software design workflows, principles, tooling defaults, habits. Everything here is the **current** answer, not a settled one: developer practice turns over fast, and these pages are expected to churn as tools and best practices evolve. Read them as "how the user works right now," not a fixed state of affairs; update them eagerly (via the pipeline) when his practice changes — a page that lags his actual practice is worse than a draft. **Boundary:** anything effort-shaped (a lifecycle, a current state) lives in projects/, whatever its domain; this folder holds what generalizes across projects. **Link direction:** project pages link here; pages here don't link out to projects/ — projects end, and those links rot. When a project teaches a generalizable practice, distill it here rather than linking back. Shareable in a redacted bundle (unlike life/, which never ships).
