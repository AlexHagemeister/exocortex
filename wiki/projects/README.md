One hub page per project (goals, current state, key decisions, links to satellites), with satellite pages for substantial sub-topics. Fed mostly by session captures and the notes sweep. Project state changes fast — prefer many small dated claims over one perpetually-rewritten narrative, so provenance stays checkable.

**Grow satellites, not sections.** A substantial new sub-topic becomes a satellite page linked from the hub — never a new hub section; edits to existing hub concerns stay on the hub. A flat hub gains its first satellite by becoming a bundle: move `<slug>.md` → `<slug>/index.md`, fix the moved page's now-wrong relative links, rewrite inbound links vault-wide, log the move in the day log. The move is mechanical and pre-approved by this rule (amendment, 2026-07-30) — nothing is reworded. A bundle's `index.md` is the authored hub page, never a derived listing — do not regenerate it; the folder needs no separate index. Each satellite link on the hub carries a one- or two-line summary of what that page holds — the hub keeps the whole project legible without opening satellites; a hub reduced to a bare link list has lost its job (amendment, 2026-07-31).
